## ✅ РЕАЛЬНЫЕ ПРОБЛЕМЫ (стоит чинить)

### MEDIUM (исправить желательно)

#### 1. Не атомарная запись иконок и .desktop
**Файл:** `src/app_config.rs:205`, `:233`

```rust
// L205
if std::fs::write(&icon_path, buf.get_ref()).is_ok() { ... }
// L233
if std::fs::write(&desktop_path, &content).is_ok() { ... }
```

**Проблема:** При сбое (power loss, OOM kill) файл может остаться частично записанным или повреждённым.

**Решение:** Запись во временный файл → `fsync` → `rename` (атомарно на POSIX):
```rust
let tmp = path.with_extension("tmp");
std::fs::write(&tmp, data)?;
let _ = std::fs::rename(&tmp, &path);
```

#### 2. `download_queue_enabled` хардкод `true`
**Файл:** `src/main.rs:1244`

```rust
download_queue_enabled: true,  // Хардкод
```

**Проблема:** В `DaemonSettings` есть `download_queue_enabled`, но в UI нет контрола. Пользователь не может отключить очередь загрузок через GUI.

**Решение:** Добавить `in-out property <bool> cfg-dl-queue-enabled` в `ui/main.slint` и связать:
```rust
download_queue_enabled: ui.get_cfg_dl_queue_enabled(),  // не хардкод
```

**Решение:** Определить enum'ы:

#### 5. `.desktop` файл всегда перезаписывается
**Файл:** `src/app_config.rs:216-236`

Текущая логика (L213: `// .desktop файл — всегда перезаписываем`):
- **Плюс:** гарантированно актуальный `Exec=` путь
- **Минус:** затирает пользовательские правки (Categories, локализация, GenericName)

**Решение (опционально):** Проверять `if !desktop_path.exists()` или дать opt-out флаг.

#### 6. Валидация `encryption` диапазона
**Файл:** `src/main.rs:1269`

```rust
encryption: ui.get_cfg_priv_encryption() as i64,  // 0,1,2
```

**Проблема:** Если UI допустит значение вне `[0..2]`, демон получит мусор.

**Решение:** `ui.get_cfg_priv_encryption().clamp(0, 2) as i64`.

#### 7. Валидация размеров изображения
**Файл:** `src/wm_icon.rs:40-41`

```rust
let img = image::load_from_memory(ICON_PNG)?.to_rgba8();
let (w, h) = img.dimensions();
```

**Проблема:** `to_rgba8()` уже гарантирует 4 канала, но `dimensions()` не проверяются на `> 0`. Теоретически `load_from_memory` не вернёт 0×0, но защитная проверка не помешает.

**Решение:** `if w == 0 || h == 0 { return Err(...); }` после `load_from_memory`.

2. **Ограничить scope** только Rust: использовать `git stash` для не-Rust файлов или явный `--include` / `--exclude` в OCR (если поддерживается)
3. **Перепроверить line numbers** — несколько раз LLM указывала L115, L0-0, L122 там, где проблем нет
